The core of Node.js is Libuv, a C library that implements the multi-platform asynchronous I/O and the Event Loop, allowing Node to handle thousands of concurrent connections on a single thread."
interviewScript: "Node.js isn't just JavaScript on the server; it's a binding between V8 and Libuv. When Node encounters an asynchronous I/O task, like reading a file or making a network request, it offloads that work to the operating system via Libuv. Libuv maintains a thread pool (default of 4 threads) for tasks the OS can't handle asynchronously. Once the OS or thread pool finishes the task, the callback is queued in the Event Loop. The Event Loop in Node has specific phases: Timers, Pending Callbacks, Idle/Prepare, Poll, Check (setImmediate), and Close Callbacks. Understanding this exact order is critical for debugging race conditions."
pitfalls:
  - "Believing Node.js is completely single-threaded (Libuv has a hidden thread pool for file I/O and crypto)."
  - "Blocking the Event Loop with heavy synchronous CPU tasks (like parsing massive JSON or regex processing)."
  - "Confusing process.nextTick() with setTimeout() or setImmediate(). nextTick executes BEFORE the event loop continues to the next phase."
  - "Loading massive files into memory at once instead of using Streams."
