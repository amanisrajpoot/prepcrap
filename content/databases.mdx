interviewScript: "Choosing a database depends entirely on the data's shape and access patterns. For structured data with complex relationships and strict integrity requirements, I default to PostgreSQL. To optimize SQL queries, I ensure proper B-Tree indexes are created, avoiding full table scans. If the data is unstructured, highly volatile, or requires massive horizontal scaling, I might opt for a NoSQL document store like MongoDB. For high-throughput key-value lookups, leaderboards, or session management, Redis is my go-to in-memory layer."
pitfalls:
  - "Over-indexing a SQL table, which speeds up reads but significantly slows down INSERT/UPDATE operations."
  - "Using a NoSQL database purely because it's 'schemaless', then ending up writing application-level schema validation anyway."
  - "Not understanding the N+1 query problem in ORMs, leading to database overload."
  - "Running complex aggregate analytics queries on a production transactional database (OLTP) instead of a data warehouse (OLAP)."
