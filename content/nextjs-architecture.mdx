concept: "Next.js App Router fundamentally shifts React from a client-side library to a server-first framework. React Server Components (RSC) allow components to render exclusively on the server, reducing bundle size and accessing backend resources directly. Client Components are pushed to the leaves of the UI tree for interactivity."
interviewScript: "In the Next.js App Router, the default paradigm is Server Components. This is a massive shift. Server Components never ship JavaScript to the client; they send a serialized representation of the UI. This means I can securely query a database directly inside my component without an API route. When I need interactivity—like onClick handlers, state, or hooks—I explicitly define a Client Component using the 'use client' directive. The key to performance in Next.js is understanding the caching layers: the Request Memoization, the Data Cache, the Full Route Cache (for SSG), and the Router Cache on the client."
pitfalls:
  - "Importing server-only modules (like 'fs' or database drivers) into a Client Component."
  - "Passing non-serializable data (like functions or Date objects) as props from a Server Component to a Client Component."
  - "Using 'use client' at the top of the component tree, effectively disabling Server Components for the entire app."
  - "Not understanding that Client Components are still pre-rendered (SSR) on the server for the initial page load."
