## Visual Concept: Stack vs Fiber Architecture

```text
 ┌─────────────────────────┐       ┌─────────────────────────┐
 │   STACK RECONCILER      │       │   FIBER RECONCILER      │
 │   (Synchronous)         │       │   (Asynchronous)        │
 └───────────┬─────────────┘       └───────────┬─────────────┘
             │                                 │
     [App Component]                  [App Component] (Priority: Low)
             │                                 │
     [List Component]                 [List Component] (Paused)
             │                                 │
 [Item 1] [Item 2] [Item 3]       [Item 1] [Item 2] ...yields to Main Thread
             │                                 │
     (Cannot pause.               (Browser handles user input, then
      Blocks Main Thread)          React resumes rendering Item 3)
```

## Deep Dive: React Fiber Architecture

The Fiber architecture is the backbone of modern React. Understanding it deeply separates senior engineers from those who just use the framework.

### The Fiber Tree

Every React element corresponds to a Fiber node. A Fiber is a JavaScript object that contains information about:

- The **component type** (function, class, host element)
- The **props** and **state**
- Pointers to its **parent**, **child**, and **sibling** Fibers
- **Effect tags** describing what DOM operations are needed

### Reconciliation Algorithm

When you call `setState`, React:

1. **Schedules** an update on the Fiber
2. **Begins work** from the root, walking down the tree
3. **Diffs** each Fiber against its previous version
4. **Collects effects** (insertions, updates, deletions)
5. **Commits** all effects to the DOM in a single batch

### Concurrent Mode

Fiber enables **time-slicing**: React can split rendering work across multiple frames. This prevents long renders from blocking the main thread, keeping the UI responsive.
