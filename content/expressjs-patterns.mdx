A middleware function has access to the request object (req), the response object (res), and the next middleware function in the application's request-response cycle."
interviewScript: "The heart of Express.js is the middleware pattern. When a request hits the server, it passes through a pipeline of functions. Each function can modify the request/response, end the request early, or pass control to the next function using next(). I always structure my Express apps with a clear separation of concerns: Routers define endpoints, Controllers handle business logic, and custom Error Handling middleware sits at the very end of the pipeline. One critical detail: error handling middleware in Express must have exactly four arguments (err, req, res, next), otherwise Express treats it as standard middleware."
pitfalls:
  - "Forgetting to call next() or res.send(), leaving the request hanging until it times out."
  - "Not catching asynchronous errors in route handlers, causing unhandled promise rejections that crash the Node process."
  - "Defining error-handling middleware before route definitions instead of at the end."
  - "Polluting controllers with database logic instead of using a service layer."

## Deep Dive: The Middleware Pipeline

Think of Express as a literal pipeline. The request flows down, and the response flows back up.
